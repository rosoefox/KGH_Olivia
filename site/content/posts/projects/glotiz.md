전북 소상공인·중소기업이 수출 지원사업에 신청할 때 필요한 **신청서 빈칸을 AI가 찾아서 자동으로 채워 주는 웹서비스**입니다.

|---|---|

## 목적

수출 지원사업에 신청하려면 공고마다 양식이 다른 신청서(HWP·DOCX·XLSX)를 매번 처음부터 채워야 합니다.
사업자등록번호, 대표자, 수출 품목, 매출 같은 **같은 회사 정보를 서류마다 반복해서 입력**하는 일이 인력이 부족한 소상공인에게는 큰 부담이었습니다.

그래서 **한 번 등록한 기업 정보와 보유 서류만으로, 새 공고의 신청서 빈칸을 AI가 찾아 자동으로 채워 주는 것**을 목표로 했습니다.

## 내 역할

4인 팀에서 **팀원**으로 참여했고, 프론트엔드를 제외한 **백엔드·AI·클라우드 대부분을 맡았습니다.**

| 구분 | 담당 작업 |
|---|---|
| 다른 팀원 | 프론트엔드 화면(React) 구현, 발표 자료 제작·발표, 지원사업 자료·데이터 조사 |
| **본인** | AI 서류 자동 작성 (서식 빈칸 탐지·자동 입력) |
| | 로그인, 관리자 화면 흐름, AI 챗봇 연동, 실제 공고 데이터 연동 |
| | AI 마케팅 이미지 생성 기능 |
| | Supabase → GCP 전체 이전 |
| | 실제 신청서 양식으로 데이터셋 구축, 빈칸 판단 모델 파인튜닝 |

## 수행 과정

### 1. 실제 신청서 양식으로 데이터셋 만들기

기업마당 등에 실제로 올라온 수출 지원사업 공고에서 **신청서 양식 약 110개(HWP·HWPX·PDF 등)**를 수집 스크립트로 내려받았습니다.
양식에서 텍스트를 뽑아낸 뒤, 각 칸이 "기업이 채워야 하는 빈칸인지, 안내 문구 같은 장식인지"를 표시해 **학습 예시 92개, 검증 예시 12개**를 만들었습니다.

### 2. 빈칸 판단 모델 파인튜닝

공고마다 양식이 제각각이고, `(서명 또는 인)`이나 `※ 안내 문구`처럼 **빈칸처럼 보이지만 채우면 안 되는 칸**이 많았습니다.
이런 칸을 매번 규칙으로 처리하기보다 실제 양식으로 학습시키는 편이 낫다고 판단해, **Gemini 2.5 Flash를 파인튜닝**하는 방식을 선택했습니다.

- 튜닝된 모델을 서비스에 연결하고, 모델 주소가 없으면 기본 모델로 자동 전환되게 했습니다.
- 학습에 쓰지 않은 실제 문서로 튜닝 전후를 비교하는 평가 스크립트를 만들었습니다.
